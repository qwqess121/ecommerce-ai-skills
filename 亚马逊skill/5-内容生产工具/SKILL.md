# 模块五：内容生产工具

> 本文件是给人看的目录说明，不是可调用的 skill。每个子目录下的 SKILL.md 才是实际工作流。

## 这个模块解决什么问题

这个模块不是排在模块三、四后面的独立步骤，而是**横向支撑**它们的内容工厂——模块三做Listing诊断需要图片和文案素材，模块四做广告需要创意素材，模块五就是随时被调用来产出这些实际素材的地方。

---

## 详细清单（含数据获取与评判标准）

### product-description-generator — 多平台产品描述生成器
**工作流**：收集产品信息 → 关键词采集（竞品抓取+搜索）→ 关键词评分分级（1-9分）→ 用FABE框架按平台规则生成文案
**获取数据 / 用哪个MCP**：卖家精灵 `keyword_research`（搜索量数据）；Brightdata `scrape`（抓竞品页面）
**评判标准**：关键词按频率/相关性/机会三维度打分后分Primary(标题)/Secondary(卖点)/Tertiary(描述)/Backend(后端)四级，Primary词必须出现在标题里，否则判定文案不合格

### amazon-storefront-design — 品牌旗舰店设计
**工作流**：收集信息 → 追问补全 → 研究页面布局和引流策略 → 交付建议
**获取数据 / 用哪个MCP**：Brightdata `scrape`（抓竞品旗舰店）；Canva `generate-design`（生成Banner/素材）
**评判标准**：页面缺少"引流到具体产品"的清晰路径时判定为需要重新设计

### amazon-product-photography — 产品摄影方案
**工作流**：建立证据与范围 → 定义视觉任务 → 构建图片架构 → 选择制作路线（DIY/AI/专业/混合）→ 制作与审核计划（三道审核门）
**获取数据 / 用哪个MCP**：Brightdata `scrape`（抓竞品主图参考）；Canva `generate-design`（AI图片初稿）；CreatoK `generate-image`（AI产品图生成）
**评判标准**：每张图必须对应一个明确的购买决策任务（识别产品/理解卖点/验证规格/场景展示/消除顾虑/了解配件/建立信任），缺失任一环节判定图片集不完整

### lyt-detail-page — 商品详情页从0生成
**工作流**：图片取证 → 产品事实卡（已确认/待确认/禁止主张）→ 选页面模式 → 规划页面模块 → 生成逐屏内容（方案版/生产版/成品版）→ 生产图片 → 全量分屏预览确认 → 交付检查
**获取数据 / 用哪个MCP**：Brightdata `scrape`（竞品详情页参考）；Canva `generate-design`（分屏设计）；CreatoK `generate-image`（场景图/信息图）
**评判标准**：每个页面模块必须能回答"解决什么疑问/用了什么事实/需要什么视觉证据/为何接在这里"，答不上来的模块判定为冗余需删除；产品身份、规格、认证、评价等信息只能用用户确认的事实，不能从参考图里带入

### lyt-image-patterns — 竞品主图样本归纳
**工作流**：建样本表 → 清洗样本 → 分组 → 打标签 → 统计共性 → 提炼公式 → 给测试方案
**获取数据 / 用哪个MCP**：Brightdata `scrape`（批量抓竞品主图URL）；卖家精灵 `asin_detail`（销量/价格数据辅助分析）
**评判标准**：只统计表达层面的共性事实（构图/视觉元素），不能把"某类型主图多"直接归因为"这类图导致销量高"，销量因果必须留给真实A/B测试验证

### lyt-image-prompt — AI图片提示词反推
**工作流**：图片取证 → 风格询问 → 提示词重建 → 产品替换与合并（可选）
**获取数据 / 用哪个MCP**：Canva `generate-design`；CreatoK `generate-image`、`optimize-prompt`
**评判标准**：产品替换时必须删除参考图原产品的身份特征（品牌、认证、评价、规格），只保留构图和视觉风格，混入原产品信息判定为违反事实闸门

### lyt-video-script — 产品短视频拍摄脚本
**工作流**：识别任务模式 → 提取产品事实 → 确定平台/目标/拍摄条件 → 建立人群-场景-需求假设 → 选核心购买理由 → 转化为镜头动作 → 收缩拍摄方案 → 一致性检查 → 合规检查 → 输出脚本
**获取数据 / 用哪个MCP**：CreatoK `generate-video`、`optimize-prompt`；Canva `generate-design`（封面/缩略图）
**评判标准**：脚本必须只服务一个核心购买理由，功效/认证/价格/优惠/对比类表述必须有事实支撑，否则判定为合规风险需要删除或改写

## 内部串联逻辑

这几个skill之间不是严格的先后链条，而是按"要产出什么类型的素材"分流：
1. 要文案 → `product-description-generator`
2. 要主图/信息图的拍摄或生成方案 → `amazon-product-photography`（有实拍素材时）或 `lyt-image-prompt`（要用AI生成时）
3. 要参考竞品主图找共性套路 → 先用 `lyt-image-patterns` 归纳规律，再用 `lyt-image-prompt` 或 `amazon-product-photography` 落地
4. 要完整详情页/A+页面 → `lyt-detail-page`
5. 要短视频 → `lyt-video-script`
6. 要品牌旗舰店页面 → `amazon-storefront-design`

产出的素材直接交给模块三（Listing图片、A+内容）和模块四（广告创意）使用。

## 竞品对比与评分（新增，2026-09-20）

内容生产的差异化判断必须基于真实竞品差评/好评证据，不是凭空设计卖点。按`../_references/竞品匹配与评分规则.md`筛出可比竞品后：
- `product-description-generator`/`lyt-detail-page`：先用卖家精灵`review`抓可比竞品的差评，找"受影响比例×严重度"评分最高的痛点（评分规则第三节），作为文案差异化的第一来源，而不是自己想象卖点
- `lyt-image-patterns`：竞品主图样本必须是过滤后的可比竞品，样本<3个要标注"样本不足"
- `amazon-product-photography`：拍摄方案里的功能特写图，应对应可比竞品评论里被反复提及但没人做到的功能缺口

## 评判标准速查表

| 检查项 | 判定标准 |
|---|---|
| 图片架构完整度 | 覆盖"识别-卖点-规格-场景-顾虑-配件-信任"7个任务，缺一即不完整 |
| 文案关键词覆盖 | Primary词必须出现在标题 |
| 产品事实合规 | 只能用用户确认信息+图片可见信息+可靠文档，不能从参考图带入身份/认证/评价 |
| 视频合规风险 | 功效/认证/价格类表述必须有事实支撑 |

## MCP 集成程度

7个全部需要人工提供具体产品信息（产品图、卖点、品牌调性）才能跑——内容生产本质上依赖你的产品是什么，不能空转。MCP（Brightdata抓竞品参考、Canva/CreatoK生成素材）在这里的作用是"减少手动找参考图、加速生成"，不是"自动产出你的产品内容"。
