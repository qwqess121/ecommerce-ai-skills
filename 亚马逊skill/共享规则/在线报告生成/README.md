# 在线报告生成（HTML 成品工具）

把一个报告目录里的模块 Markdown（1 份到 5 份都可以），拼成单页 HTML 报告 `report.html`。只有一个模块时，也能单独出 HTML。格式要求见 `../报告格式/输出格式强制规定.md`。

## 目录里需要的文件

- `模块1-*.md` … `模块5-*.md`：任意几份，前缀决定顺序。只放一份时，报告只包含这一个模块。
- `overview.json`（可选）：`title`、`brand_name`、`brand_sub`。缺省时标题取第一个模块的 H1，品牌名为空。
- `overview.html`（可选）：总览页正文。有则作为第 00 页；没有则报告从模块页开始；此时第一个模块页的标题下会自动出现模块卡片（链接 `#m1` … `#m5`），格式见 `../报告格式/报告格式规范.md` 3.3

## 用法

```bash
cd 共享规则/在线报告生成
npm install            # 首次
node convert.js "<报告目录>"
node build.js "<报告目录>"
```

产物：`<报告目录>/report.html`。脚本不再写死任何路径或 ASIN，换报告只需换目录。

## 注意

- 区块标签必须写成加粗段首（`**小结** —— …`、`**发现** —— …`），模板据此上色。正文不写 `结论`、`依据`、`含义与置信度` 三段式标签（见 `../报告格式/输出格式强制规定.md` 第 3 节）。

## 颜色规则

区块颜色由 `template.html` 里的 `BLOCK_RULES` 决定，按段首加粗标签匹配，先命中先生效：

| 标签 | 颜色 | class |
|---|---|---|
| 小结 | 蓝紫 | `summary-block` / `summary-label` |
| 发现 | 琥珀 | `finding-block` / `finding-label` |
| 含修正、限制、缺口、未完成、风险、警告 | 红橙 | `warning-block` / `warning-label` |

颜色同时作用于区块的文字与左侧边线，明暗两种主题都已定义。改颜色只改模板，不改报告正文。
- 模块 4 的 H1 固定为 `模块四·广告策略分析 —— <本品名>`。
- 发布 Artifact 时，后续更新必须带上第一次返回的 `url`。

## 交付前检查（必做）

- 成品 `report.html` 必须在**无脚本环境**（静态预览、邮件附件）下内容可见。模板已将分页显示改为"脚本运行后才隐藏非当前页"（`html.js section.page`），所以静态预览会显示全部页面。
- 检查方法：用不执行脚本的方式打开 HTML（例如用浏览器的"查看源代码"，或在文本中确认每个 `<section class="page">` 的正文都在），并确认 `template.html` 中不存在无条件的 `section.page{display:none}`。
- 修改模板后必须重新运行 `convert.js` 与 `build.js` 生成 `report.html`，再发给用户；不要只替换模板而不重建。
- **多模块报告的模块分隔**：脚本运行时一次只显示一个模块，无脚本时所有模块同时显示。模板对无脚本状态加了粗分隔线（`html:not(.js) section.page + section.page`），模块之间不得首尾相接。改模板时保留这条规则。
- **引导块（`div.guide`）内不写 Markdown 链接语法**。HTML 块里的 `[文字](url)` 不会被渲染，会原样显示。ASIN 直接写成纯文本，构建脚本会自动加上亚马逊链接。
- 验证方法：用关闭脚本的浏览器（如 Playwright 的 `javaScriptEnabled: false`）打开成品，确认模块之间有分隔、引导块里没有原始 `[..](..)` 文本。
