# 取数手册（给 Claude 执行，其他电脑同样适用）

本手册说明报告所需的每一份数据：调用哪个工具、传什么参数、保存到哪个文件。**取数由 Claude 直接调用 MCP 工具完成，不是脚本。** 每一步都要先看到工具真实返回，再保存；不要凭记忆编造参数或数字。

## 0. 开始前必须确认

1. **MCP 是否可用**：调用 `mcp__b4c2f5aa-0989-42bf-95ac-ff4bfb0a12a8__ping`（Sif）。失败则停止，告诉用户"Sif MCP 未连接"。
2. **卖家精灵是否可用**：调用一次 `asin_detail`（marketplace=US，asin=本品）。失败则停止。
3. **领星是否可用**（只用于广告花费、ACOS、库存）：调用 `mcp__LingXing-MCP__help`（query="产品表现"）获取工具 ID；再调用 `mcp__LingXing-MCP__search`（toolId=…）读取入参；最后用 `mcp__LingXing-MCP__action`（toolId, params）执行。领星失败不阻断报告，但对应章节必须写"未取（原因：领星未连接）"。
4. 确认站点为 `US`，确认本品 ASIN 与父体 ASIN。

## 1. 变量约定

| 变量 | 含义 | 来源 |
|---|---|---|
| `OWN` | 本品 ASIN | 用户给出 |
| `PARENT` | 父体 ASIN | asin_detail 的 `parent` 字段 |
| `NODE` | 类目节点路径（nodeIdPath） | asin_detail 的 `nodeIdPath`，例如 `3760911:11056591:11056931:11057071` |
| `COMPS` | 真竞品 ASIN 列表（最多 5 个） | 由 竞品门槛.py 按本手册第 3 步推导后选出，缺额如实记录 |
| `HEAD` | 头号流量词 | traffic_keyword 中 trafficPercentage 最高的词 |
| `DIR` | 数据目录 `数据-<OWN>/` | 与本手册同级，由 Claude 创建 |

数据目录必须按下面的文件名保存。取数完成后运行 （取数完整性检查.py 未迁入本文件夹，改为按本文件的文件清单人工核对） 检查。

## 2. 第 1 步：本品与对象详情

**工具**：卖家精灵 `asin_detail`，参数 `{marketplace:"US", asin:<ASIN>}`。对本品和五个真竞品各调用一次（可并行）。

**保存**：
- `DIR/listing/asin_detail.json`：仅本品的返回原文。
- `DIR/listing/asin_detail_6.json`：合并格式
  ```
  {"source": "...", "items": {"<ASIN>": {"brand":..., "price":..., "rating":..., "ratings":..., "lqs":..., "bsrRank":..., "coupon":""}, ...}}
  ```
  本品放第一个。`price` 用返回的当前价，`lqs` 可为 null。

## 3. 第 2 步：候选池（价格带内分页）与真竞品判定（程序化）

竞品门槛不写死在品类里，而是从本品数据推导。流程分三步，顺序不能颠倒。

**(a) 先确定门槛配置**（写入取数配置.json 的 gate 字段）：
- `price_band`：价格带倍数，默认 `[0.6, 1.4]`（±40%）。真竞品不足 5 个时才放宽，顺序 `[0.4, 1.6]`（±60%）、`[0.2, 1.8]`（±80%），见 `竞品判定标准.md`。
- `search_keyword`：**正式取数必须留空**，候选池按整个节点取。实测 `keyword=pheromone` 会漏掉标题写 "Pheromones" 或只含 "Roll On" 的同类产品（VivaFemme、Elara Botanica、NQJYXZP 均未返回），关键词只能作为人工参考，不能作为池子的来源。
- `max_n`（真竞品数，默认 5）、`backup_n`（备选数，默认 5）。

**(b) 分页取候选池**（程序自动追加页）：
- 卖家精灵 `product_research`，参数由取数清单的 `node_pool` 生成：`nodeIdPath`、`month`、`minPrice`/`maxPrice`（由本品售价×价格带算出）、`keyword`、`matchType=1`、`page`、`size=50`。
- **必须取全部页。** 第一页返回的 `data.pages` 决定总页数；只看第一页会漏掉销量低的品牌（这是一次真实的错误：只看了 8 页中的第 1 页）。取数流程会自动生成第 2 页及之后的任务。
- 保存为 `DIR/candidates/pool_band_p<页码>.json`（每页原文）。

**(c) 运行竞品门槛脚本**：
```
python -X utf8 工具/竞品门槛.py <DIR>
```
脚本做的事：
1. 从本品详情推导形态族（标题对照 `竞品门槛词表.json`），本品标题无法归类时直接报错，需要补词表。
2. 过滤候选：价格带内；节点路径相同；形态族相同；使用场景族相同（如 pheromone，`designer_dupe` 即名牌平替不计入）；人群不相反（标题只写男性的不计入女性本品）；标题不含排除词（如 refill）；不是本品；不是同品牌（同品牌其他 ASIN 归为内部关联）。
3. 同一品牌只保留单品销量最高的一个 ASIN，避免同一卖家的多个变体占满名额。
4. 按销量取前 `max_n` 个作为真竞品，接着取 `backup_n` 个作为备选。不足 `max_n` 时写 `shortfall`，**不得用其他形态凑数**。
5. 缺页时拒绝运行（退出码 1，列出缺失的页）。

输出：`candidates/gate.json`（推导出的全部门槛参数与各类排除计数，可审计）和 `candidates/true_competitors.json`（真竞品、备选、缺额、判定依据）。

运行后用 `取数流程.py manual <DIR> judge_competitors` 标记完成。**报告必须写明缺额和门槛依据**（来自 gate.json）。

**同品牌的其他规格**（如同一卖家的 12 ml 旅行装、或同品牌的其他变体）列为内部关联，不计入竞品，也不占用名额。

## 5. 第 4 步：销售序列

- 卖家精灵 `asin_sales_trend`，参数 `{"marketplace":"US","asin":<ASIN>}`，对本品与五个真竞品、三个备选各调用一次。
- 保存为 `DIR/sales/competitor_trend_2026.json`：每个对象一条 `series`，包含 `parent_units`（按月）、`child_units`、`parent_revenue`（月）、`price`（2026-09）、`ratings`、`bsr`、`first_rating_date`、`variations`、`seller`。null 必须保留，不能写成 0。
- 变体：Sif `ops_get_asin_sales_trend`，参数 `{"asin":PARENT,"country":"US","dimension":"asin"}`。保存为 `DIR/sales/variants_<PARENT>.json`（13 个变体按 asin 返回的 `chars` 逐个保存，月销 `bought` 保留 null）。

## 6. 第 5 步：流量

| 工具（Sif） | 参数 | 保存 |
|---|---|---|
| `ops_get_listing_traffic_overview` | `{"asin":OWN,"country":"US","timePieceType":"latelyDay","timePieceValue":"30"}` | `DIR/traffic/overview_<OWN>.json` |
| `ops_get_listing_traffic_overview`（每个对象） | 同上，asin 换成各对象 | 合并为 `DIR/traffic/competitor_traffic_overview.json`（items 数组：asin、name、total_score、nf_ratio、ad_ratio、ad_sp_normal、ad_sp_recommend、ad_sb） |
| `ops_get_asin_traffic_trend` | `{"asin":ASIN,"country":"US","granularity":"week","lastMonths":6}`，对本品与五个真竞品 | 本品：`DIR/traffic/weekly_<OWN>.json`；对象：合并为 `DIR/traffic/weekly_competitors_202610.json` |

周流量只保存 `totalScore` 数组、`dates` 数组，并计算近 13 周均值、前 13 周均值与变化。

## 7. 第 6 步：广告

1. **广告规模（历史）**：Sif `ads_get_asin_ad_structure`，参数 `{"asin":ASIN,"country":"US","granularity":"month"}`，对每个对象各一次。合并为 `DIR/ads/competitor_ad_structure.json`（items：asin、role、SP、SB、SBV、total）。
2. **本品曝光贡献**：Sif `ads_get_asin_campaign_contribution_overview`，参数 `{"asin":OWN,"country":"US","start_date":"2026-04-01","end_date":"2026-09-30","limit":20}`。保存为 `DIR/ads/campaign_contribution_<OWN>.json`。
3. **广告组与关键词归属**：对第 2 步返回的每个 campaign：
   - Sif `ads_get_campaign_structure`，参数 `{"asin":OWN,"campaignId":<campaign_display_id>,"country":"US"}`，得到 adGroups。
   - 对每个 adGroup：Sif `ads_get_ad_group_keyword_breakdown`，参数 `{"asin":OWN,"campaignId":...,"adGroupId":...,"date":<该周周日，如 2026-09-06>,"country":"US"}`。
   - 报错（如 "adGroupId is not found"）的组，记录原文，不要猜。
   - 合并为 `DIR/ads/adgroup_keywords_all.json`，每组含 campaign、campaign_type、ad_group、keywords（关键词数）、date、display_asins、status（ok/error）。
4. **领星效率**（只限本店铺）：领星 `action`，参数按 search 返回的 inputSchema 构造，查询 2026-09 整月的 `query_product_performance_asin_lists`（搜索字段 asin，货币 USD，date_type=purchase）。保存为 `DIR/ads/lingxing_<OWN>_202609.json`，至少包含花费、广告销售、ACOS、TACOS、CPC、CVR、CPO、毛利率、FBA 可售、总库存。领星与卖家精灵的数字口径不同，写报告时分开引用。

## 8. 第 7 步：关键词

1. **本品流量词**：卖家精灵 `traffic_keyword`，参数 `{"request":{"asin":OWN,"marketplace":"US","size":100}}`（不带 month）。保存为 `DIR/keywords/<OWN>.json`，包含 `top` 数组（keyword、searches、trafficPercentage、purchaseRate、naturalRankPosition、adRankPosition）。取流量占比最高的词作为 `HEAD`。
2. **头号词的 Sif 数据**：
   - `market_get_keyword_demand`，参数 `{"keywords":[HEAD],"country":"US"}`
   - `market_get_keyword_competition`，参数 `{"keyword":HEAD,"asin":OWN,"country":"US"}`
   - `market_get_keyword_history`，参数 `{"keywords":[HEAD],"country":"US","granularity":"month"}`
   - 保存为 `DIR/keywords/headword_sif_202610.json`。
3. **关联流量反查**：卖家精灵 `traffic_extend`，参数 `{"request":{"asinList":[ASIN],"marketplace":"US","queryType":2,"size":10,"order":{"field":"trafficPercentage","desc":true}}}`，对本品与对标（For Her、Magic Energy 等）各一次。合并为 `DIR/ads/traffic_extend_202610.json`。
4. **关键词转化估算**：卖家精灵 `keyword_conversion`，参数 `{"request":{"keyword":K,"marketplace":"US","timeType":"90D","size":5}}`，对 HEAD 与一个香型词各一次。保存为 `DIR/ads/keyword_conversion_202610.json`（只保留 searches、clicks、purchases、转化率、phrase PPC、phrase CPA）。

## 9. 第 8 步：评论

- 卖家精灵 `review`，参数 `{"marketplace":"US","asin":ASIN,"starList":[1,2,3],"size":100}`，对五个真竞品与本品各一次。
- 保存为 `DIR/reviews/<ASIN>_neg_cn.json`（对象）与 `DIR/reviews/<OWN>_neg.json`（本品）。
- 工具返回 0 条时，原样保存 `items: []` 并写 `note`。**不得写"无差评"。** 写报告时说明样本量为 0，并建议人工核对。
- 本品的差评需要逐条人工分类（香型、留香、香味太浓、其他），保存为 `DIR/reviews/<OWN>_classification.json`，写明分类依据与条数。

## 10. 第 9 步：图片与 A+

1. **文字与 A+**：`node 2-竞品销售策略分析/amazon-review-insights/scripts/amazon_listing_capture.js --asins <六个ASIN，逗号分隔> --out DIR/listing/listing_capture_all.json`。被拦截时改用 `--headed`。
2. **图片与视频抓取**：`node 2-竞品销售策略分析/amazon-review-insights/scripts/amazon_image_capture.js --asins <六个ASIN> --video --frame-interval 3 --download --outdir DIR/images --out DIR/images/images.json`。视频为 mp4 直链，每 3 秒抽一帧；抽帧需要 ffmpeg（PATH 或环境变量 `FFMPEG`，无则 `pip install imageio-ffmpeg`）。完整流程见 `共享规则/图片标准.md` 第零节 0.1。
3. **整理与读图**：抓取的图片按 `DIR/images/<ASIN>_NN.jpg`（视频帧在 `DIR/images/frames/`）存放，不做拼版。用 Read 工具逐张读原图，读完一张记录一张。
4. **逐张读图**：用 Read 工具读原图，逐张记录到：
   - `DIR/images/analysis/main_<ASIN>.json`：items 数组，每项含 idx、kind（图片类型）、visible_text（图上可读文字，看不清写"小字不清"）、claims（功效或数字声明）、violation（违规点）、bg（背景）。**items[0] 必须写 `main_class`**：纯白底且无道具写 `pure_white`；白底但道具在产品旁写 `white_with_props`；背景为色块、场景、渐变或灰底写 `scene_or_color`。
   - `DIR/images/analysis/aplus_<ASIN>.json`：同格式，覆盖每一张 A+ 图。
   - 视频：逐帧读取 `DIR/images/frames/` 下的帧，写入 `DIR/images/analysis/video_<ASIN>.json`（每帧一条：时间点、画面主体、画面文字、是否有水印）。全部帧读完才算完成。只有 HLS（.m3u8）未取到时，才写"视频未审计"并写明原因；不得只凭封面写视频内容。

## 11. 第 10 步：派生值登记

报告中所有比例、合计、差额、单位价格、转化代理等派生数字，都要在 `DIR/数据核对_允许值.json` 的 `entries` 中登记 `{"value": 数字, "说明": "计算式与来源文件"}`。`数据核对.py` 会检查正文中的数字是否都能在数据文件或这个表中找到。

## 12. 完成检查

运行：
```
python -X utf8 （取数完整性检查.py 未迁入，改为人工核对文件清单） <DIR> <OWN> <COMP1,COMP2,COMP3,COMP4,COMP5> <PARENT>
```

## 常见问题

- **工具返回报错**：记录原文，换参数重试一次；仍失败则写"未取（原因：工具返回 <原文>）"。
- **同一指标两个工具口径不同**：两个数都保留，并注明口径。不要混用。
- **领星与卖家精灵的销量不同**：领星是子 ASIN，卖家精灵是父体家族，分开写。
- **不要用 month 参数调 traffic_keyword**：会返回 0 条。

## 十、版本 2 的展开与 Top15（2026-10-08 第二轮）

取数清单升级为版本 2，展开顺序如下，每一步都要用 `取数流程.py next` 确认下一个任务，不要跳步：

1. 本品详情 `own_detail`，候选池 `node_pool`（逐页），再运行 `竞品门槛.py <DIR>` 写真竞品（`judge_competitors`）。
2. 节点 Top15 `node_top15`（`nodeIdPathEqual: true`，按月销量降序前 15，不做价格筛选），再运行 `选类目Top15.py <DIR>`（`judge_top15`）。
3. 执行 `取数流程.py expand <DIR>`：把对象展开为 本品 + 真竞品 + Top15（去重）。展开后出现的逐对象任务（详情、销量序列、流量概览、周流量、广告结构、差评、好评、listing 抓取、主图、A+）都要逐个取完。
4. 节点层、头号词层的任务与对象无关，可在第 1 步之前完成。头号词 `head_keyword` 由人工写入 `取数配置.json` 后，`needs: head_keyword` 的任务才会出现。
5. 修改清单后先运行 `校验取数清单.py`（退出码 0 才可用）。

完成后按本文件的文件清单人工核对，全部齐全才能进入写报告。

## 十二、差评与分类（第四轮修改）

- 评论接口每次只返回第 1 页 20 条，即使请求 `size=100`。返回的 `total` 为全量条数，`hasNextPage` 表示还有后续页。
- 报告只使用第 1 页样本，并在正文写明样本条数与全量条数。需要更大样本时，应按 `page` 参数逐页取数（每页单独保存为 `reviews/<ASIN>_neg_p<页码>.json`），并在分类文件中合并；当前清单未包含分页取数任务。
- 分类规则见 `差评分类规则.md`；分类结果用 `工具/差评分类.py` 生成与统计，报告中的差评数字只能引用其 `summary`。
