## 零、为什么需要这一层（一句话）

**单时点、单口径、单来源的报告必然是薄的。**

只报「ACOS 25.39%」「评分 4.2」「差评率高」——这些是**症状**，不是诊断。厚度来自四件事：

| 缺什么 | 症状 | 补法 |
|---|---|---|
| 缺利润分母 | 说得出 ACOS，说不出"这个 ACOS 还能撑多久" | **L1** |
| 缺时间轴 | 说得出"现在差"，说不出"在变好还是变坏" | **L2** |
| 缺归因下钻 | 说得出"广告占比"，说不出"钱花在哪个词、哪个载体上" | **L3** |
| 缺对照差集 | 说得出"差评率 31.6%"，说不出"哪条缺陷只有我有" | **L4** |

> ⚠️ **数据利用率纪律（实测，2026-09-18 复核）**：Sif MCP 挂载 **34 个工具**、领星 **276 个**（`help` 返回 `total: 276`；此前误记为 137）。早期报告只用了 Sif 的 4 个（~12%）、领星的 1 个（**0.4%**）。**被闲置的恰恰全是提供深度的工具**。问题从来不是"数据不够"，是"数据拿到了只用了一成"。
> **工具数会变**：领星 2026-09-01 是 137 个，2026-09-18 已是 276 个。**每次核对都要重新调 `help` 取 total，不要引用记忆里的旧数字。**
> **执行要求：每个模块跑完，必须核对本文件第三节的「工具核对清单」——未说明为何不用的深度工具，视为流程未完成。**

## 一、四个深度层定义

### L1 · 单位经济学层（P&L Decomposition）

**回答的问题**：这门生意每件赚不赚钱？利润被谁吃掉？还有多少安全垫？降价/加广告/促销的天花板在哪？

**触发条件（任一命中即必须执行）**
- 报告里出现任何利润、毛利、净利、盈亏平衡、利润红线、出价上限的结论
- 涉及定价调整、促销 ROI、预算再分配
- 模块一的新品可行性测算、模块二的定价红线、模块四的出价上限

**必调工具**

| 工具 | 拿什么 | 关键字段 |
|---|---|---|
| 领星 `query_order_profit_list` | **本品**全费用明细（唯一真实来源） | 采购/FBA 配送/佣金/广告/促销折扣/仓储/弃置/承运人/退款/运费收入/库存赔偿 → `gross_profit` |
| Sif `market_estimate_profit_threshold` | 采购成本**上限反推**（本地费率表算，无外部依赖） | `purchase_cost_ceiling`（淡/旺双算 + `negotiation_target`）、`breakdown`、`logistics`、`notes` |

**输出物（缺一即不合格）**
1. **费用瀑布表** —— 每个费用项给出「金额 + 占销售额 %」，从销售额逐项减到净利
2. **盈亏平衡表** —— 盈亏平衡 TACOS / ACOS、当前实际值、**安全垫（pt）**
3. **采购成本超支额** —— 当前 COGS vs 反推上限，给出「压到位后净利会变成多少」
4. **口径结论** —— 明确写明领星 `gross_profit` 是**已扣广告费后的净利**（实测反推吻合度 91%），避免与"毛利"混用

**硬性纪律**
- **绝不用卖家精灵的类目 profit 字段冒充真实利润**（实测两者差 5 倍：类目估算 52% vs 真实 11%）
- 计价重按**实重 vs 体积重取大**判定；尺寸分档决定费率档位，先确认档位再谈降本
- 未纳入核算的成本必须显式列出（广告费率、退货损耗、出口退税/HS 编码），标注"未计入"而不是当作 0

### L2 · 时间趋势层（≥90 天日级序列）

**回答的问题**：在变好还是变坏？拐点在哪天？是自身问题还是品类共同事件？

**触发条件**
- 任何方向性判断词：增长 / 下滑 / 稳定 / 反弹 / 恶化 / 恢复
- 任何"某指标高/低"的对标判断（高/低只有相对时间或相对竞品才有意义）
- 归因分析的基线构造（**必须先剔除共因事件**）

**必调工具**

| 工具 | 拿什么 |
|---|---|
| Sif `ops_get_asin_traffic_trend`（`granularity=day`） | 日级：总流量 / 自然 / 广告 / SP / SB / SBV 得分 + 价格 / BSR / 子类 BSR / 评分 / 评论 / 卖家数 |
| Sif `ops_get_asin_sales_trend` | 销量/销售趋势 |
| Sif `ads_get_asin_ad_traffic_trend` | 广告流量趋势（广告占比演变） |
| Sif `market_get_keyword_history` / `market_get_keyword_root_trend` | 关键词需求历史 |
| 卖家精灵 `asin_sales_trend` / `asin_coupon_trend` | BSR/价格历史 + 促销节奏 |

**输出物（缺一即不合格）**
1. **≥90 天序列**，至少覆盖：BSR（大类 + 子类）、价格、评论数、评分、流量结构
2. **方向判定** —— 用工具自带的 `overall_direction`（growing / mild_growth / stable / mild_decline / declining / insufficient_data），不自创标签
3. **异常日清单** —— `anomaly_weeks[]`，并给出判读（自身问题 or 共因）
4. **共因事件剔除** —— 多个对照对象**同日命中异常**的日子，必须标为平台/品类级事件，从归因基线中剔除
5. **分段均值表** —— 把窗口切成 ≥6 段，看结构（如广告占比）的演变，而不是首末两点

**硬性纪律**
- **单时点快照不得下趋势结论。** 样本 <60 天时只能给"不足以下结论"
- 本品与竞品**必须同窗口、同粒度**，否则不可比
- 价格/促销变更点必须单独列出（价格是流量的上游变量，不排除就无法归因）

### L3 · 广告归因层（Campaign → 搜索词）

**回答的问题**：广告费具体花在哪个 campaign、哪个词、哪个 ASIN 载体上？哪些词该加价、该否定、该升级？

**触发条件**
- 任何广告诊断、出价调整、否词、预算再分配结论
- 任何"ACOS 偏高/偏低"的定性判断（必须先归因到词，否则无法行动）

**必调工具**

| 工具 | 拿什么 | 用途 |
|---|---|---|
| Sif `ads_get_asin_campaign_contribution_overview` | campaign 级曝光贡献排序（`share` / `contribution_tier`：dominant≥30% / major≥10% / supporting≥3% / minor<3%） | 找头部集中度与僵尸 campaign |
| Sif `ads_get_campaign_contribution_breakdown`（`breakdown_by=keyword`） | 关键词级：`traffic` 曝光得分 / `trafficShare` / `adRankHistory`（**SP 广告槽序号，按周**）/ `naturalRankHistory`（**自然位，按周**）/ `searchTrend`（37 周搜索量 + 搜索排名） | 四象限主表 |
| Sif `ads_get_campaign_contribution_breakdown`（`breakdown_by=ad_group`） | 广告组级 —— **下钻到实际投放的变体 ASIN** | 发现载体错配 |
| Sif `ads_get_ad_group_keyword_breakdown` | 广告组内关键词流量占比 | 补充 |
| 卖家精灵 `traffic_keyword` | **自带 `conversionKeywordType`（excellent 转化优质 / stable 平稳 / lost 流失 / invalid 无效曝光）** + 自然位 + 广告位 + 流量占比 + PPC 竞价 | **四象限的权威来源，优先于自建分类** |
| 领星 `ad_campaign_report` | 本品真实花费/ACOS/ROAS/CVR/CPC | 与曝光口径交叉验证 |

**输出物（缺一即不合格）**
1. **Campaign 下钻表** —— 贡献排序 + 集中度判断（头部占比 / 长尾僵尸数）
2. **载体核查** —— 广告组实际投放的 ASIN vs 被审计 ASIN，两者不一致即为**载体错配**，必须单独说明
3. **四象限表** —— 流量贡献 × 转化效率，四类（高转高花 / 高转低花 / 低转高花 / 低转低花）
4. **三张可执行清单** —— ①否定词清单 ②竞价调整清单 ③预算再分配清单，每条带数据依据
5. **口径声明** —— 每个"某词排名 / 某词无覆盖"的结论必须标注用的是哪一套口径（见第二节）

**硬性纪律**
- **泛词不是否定词。** 高流量低转化但 `adPosition` 为 null 的词，吃的是**自然流量的份额分母**，不是广告费——不可当否词
- 竞品花费拿不到（领星只有本品），所有竞品花费规模**必须标注为估算**
- 广告位排名与自然位排名是两回事，两者都要给，不能只给一个

### L4 · 评论差集层（本品 vs 竞品）

**回答的问题**：哪些缺陷只有我有（必须修）？哪些缺陷只有竞品有（可攻击）？哪些是品类通病（说了没用）？

**触发条件**
- 任何 Listing 改写、五点重写、A+ 内容、图片任务定义
- 任何内容提示词产出（**差评痛点必须转成提示词的负向约束/必答顾虑**）
- 任何产品改进优先级、质检方向
- 任何"差评率高"的定性判断

**必调工具**

| 工具 | 拿什么 |
|---|---|
| 卖家精灵 `review`（`starList:[1,2,3]`） | 结构化差评：星级/标题/正文/日期 |

> ⚠️ **`review` 的 `size` 参数无效，固定返回 20 条/页** —— 要 100 条必须分 5 次调，靠 `page` 翻页。

**输出物（缺一即不合格）**
1. **样本声明** —— 每家样本量 + 差评池总量 + 抽样覆盖率
2. **主题聚类表** —— 主题 / 频次 / 占比 / 严重度 / 客户原话
3. **差集矩阵**（核心）——
   | 象限 | 含义 | 处置 |
   |---|---|---|
   | 仅本品有 | 自身缺陷 | 必修（按频次×严重度排序） |
   | 仅竞品有 | 可攻击面 | 写进 Listing / 广告创意 / 对比图 |
   | 两家都有 | 品类通病 | 不作为差异点，只能做"我做得更好" |
   | 都没有 | 未表达需求 | 转模块一产品开发 |
4. **每条差评必须给归属** —— 本品问题 or 竞品问题 or 通病，不允许混着写
5. **置信度标注** —— 样本 <30 条时标"低置信"，不下"结构性问题"结论

**硬性纪律**
- **差评率必须与本品的评分数一起看。** 评分数只多 16% 而差评数是对方 3.1 倍，才是真问题（分母陷阱）
- 一条差评归因到"配方/工艺/设计"之前，必须能定位到具体可改的物理部件或参数
- 客户原话**原文引用**，不转述不美化

## 二、三口径纪律（本文件最重要的一节）

**同一关键词在不同工具下是三个完全不同的数字，混用必误判。**

| 口径 | 工具与字段 | 实际含义 | ❌ 不能用来回答 |
|---|---|---|---|
| **ASIN 级汇总** | Sif `market_get_asin_keyword_signals` → `sp_rank` | 该 ASIN 在该词上的 SP 汇总信号，**可能为 null** | "有没有投这个词" |
| **Campaign 级** | Sif `ads_get_campaign_contribution_breakdown` → `adRankHistory.rank` | **SP 广告槽内的序号**（如 p1 8/12） | 页面上实际排第几 |
| **页面槽位** | 卖家精灵 `traffic_keyword` → `adPosition.index` | **搜索结果页整体槽位**（如 p1 54/58） | SP 广告位排名 |

**强制规则**

> **任何"某关键词无广告覆盖 / 广告未投 / 排名缺失"的结论，必须同时给出 ASIN 级与 Campaign 级两个口径。**

**已发生的误判案例（务必引以为戒）**：早期模块四报告据 `sp_rank: null` 得出「头号流量词 `car air freshener` 无 SP 覆盖」——实际该词有大量 SP 投放，只是**投放载体不是被审计的那个 ASIN**（详见 L3 载体核查）。结论方向完全错了。

## 四、工具避坑清单（实测踩过的坑，直接照做）

| # | 坑 | 正解 |
|---|---|---|
| 1 | `ops_get_asin_traffic_trend` day 粒度返回 **86KB+**，直接进上下文会超 token | **必须落盘 + Python 解析**，只把聚合结果带回来 |
| 2 | 该接口 `totalScore`/`nfScore`/`adScore` 等是**嵌套字典** `{score, scoreRatio, scoreChange, scoreChangeRatio}` | 取值前判 `isinstance(v, dict)`；只有 `bsr`/`star`/`review`/`price` 是裸值 |
| 3 | `subBsr` 是 **KV 结构**（`{"Air Fresheners": [...]}`）不是数组 | 先取 `list(sub.keys())[0]` 再取序列 |
| 4 | `week`/`month` 粒度**不返回**价格/排名/评分字段 | 要趋势细节必须用 `granularity=day` |
| 5 | Sif `ads_get_campaign_contribution_breakdown` 的日期**有硬约束** | `start_date` 必须是**周日**，`end_date` = start + 6 天 |
| 6 | `ads_get_ad_group_keyword_breakdown` **只有流量占比、没有转化数据** | 转化效率要用卖家精灵 `traffic_keyword` 的 `conversionKeywordType` 或市场购买率作代理，并标注为代理指标 |
| 7 | 卖家精灵 `review` 的 `size` 参数**无效**，固定 20 条/页 | 靠 `page` 多次调用 |
| 8 | 领星 `help` 接口用**模糊中文** query 会返回 `{"code":-1,"subMsg":"gw"}` | 用**英文 toolId 关键词**查询（`search_term_report` / `profile`） |
| 9 | 领星域名偶发 `getaddrinfo ENOTFOUND openmcp.lingxing.com` | **会自愈**，稍后重试即可，不要判定为"权限失效" |
| 10 | 平台级共因事件污染归因 | 多对照对象**同日异常**的日子必须剔除（实例：2026-08-05~06 四家全部命中） |

## 五、置信度标注规范（所有数字都要带）

| 等级 | 含义 | 典型来源 |
|---|---|---|
| **A** | 直接测量 | 领星真实花费/利润、卖家精灵评论原文 |
| **B** | 同口径推算 | 由 A 级数据按明确公式推导（如盈亏平衡 TACOS） |
| **C** | 代理指标 | 用市场级购买率代理关键词转化率、用曝光得分代理流量 |
| **D** | 估算 | 竞品花费规模、竞品成本结构 |

**样本量阈值**：评论 ≥100 条 = 高；30–99 = 中；<30 = 低（不给"结构性"结论）。

**禁止**：把 C/D 级数据写成 A 级语气。任何"竞品花费/竞品成本"必须带"估算"。

## 八、与其它共享规则的关系

```
共享规则/竞品判定标准.md   →  决定「跟谁比」      （选对象）
共享规则/深度分析层.md     →  决定「分析多深」    （够不够厚）
共享规则/交叉验证规则.md   →  决定「结论可不可信」 （是不是真）
```

| 规则 | 回答的问题 | 缺了会怎样 |
|---|---|---|
| `竞品判定标准.md` | 跟谁比？ | 跟错对象比，**结论方向全错** |
| `深度分析层.md`（本文件） | 分析多深？ | 报告薄，**只有症状没有诊断** |
| `交叉验证规则.md` | 结论可信吗？ | 数据都对，但**单源支撑，错了无法自知** |

> **执行顺序固定**：先筛竞品 → 再做深度层 → 最后跑交叉验证 → 过自查清单 → 才可交付。
> 三份都过，报告才同时满足「**方向对、有厚度、可追溯**」。

### 各层必做交叉验证的环节（速查）

| 层 | 必须交叉验证的结论 | 主源 → 独立第二源 |
|---|---|---|
| **L1** | 真实利润 / 成本结构 | 领星 `query_order_profit_list` → Sif `market_estimate_profit_threshold` 反推上限 |
| **L2** | 趋势方向 / 拐点 | Sif `ops_get_asin_traffic_trend` → 卖家精灵 `asin_sales_trend` / `google_trend` |
| **L3** | 「某词有无广告覆盖」（**否定式，强制双源**） | Sif ASIN 级 `sp_rank` → 卖家精灵 `traffic_keyword.adPosition` |
| **L3** | 投放载体归属 | Sif `ads_get_campaign_contribution_breakdown`（`breakdown_by=ad_group`）→ 领星 `ad_campaign_report` |
| **L4** | 差集矩阵每个象限 | 卖家精灵 `review`（本品）→ 同口径竞品 `review` |
| **通用** | 变体 / Listing 归属 | `ops_get_listing_traffic_structure`（**双向入口各调一次**）→ 卖家中心变体管理页 |
