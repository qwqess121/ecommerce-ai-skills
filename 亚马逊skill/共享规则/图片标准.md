## 零、取数方法：图片从哪来（🔴 必读，判定前的前置步骤）

> **血债（2026-09-28 立）**：模块三/五多次因为"拿不到图片"而把结论降级成推断（"主图信息量推断偏低""竞品主图归纳因样本不足不构成标准"），但实际是**没找对取图方法**，不是真的拿不到。MCP 工具（卖家精灵 `asin_detail` 等）本来就只返回 1 张 `imageUrl`/`zoomImageUrl`，**从来不是完整图库**——这是工具设计如此，不是"这次凑巧拿不到"，每次做图片相关判定都要按下面的优先级主动去取，不能等 MCP 返回空就直接降级为推断。

**取图优先级（从上到下，前一条能用就不用后一条）**：

| 优先级 | 方法 | 是否需要登录/配置 | 能拿到什么 | 适用场景 |
|---|---|---|---|---|
| ① 首选 | `2-竞品销售策略分析/amazon-review-insights/scripts/amazon_image_capture.js`（Playwright脚本） | **不需要**，装了 Node + Playwright 即可跑（`amazon-review-insights/SKILL.md` 有环境准备步骤） | 完整图库真实原图 URL（原始顺序）+ 视频占位数；`--download` 存图片；`--video` 点击视频缩略图下载 mp4（HLS 仅记录地址）；`--frame-interval N` 用 ffmpeg 抽帧。均可存本地供 Read 工具直接看图/逐帧分析 | **默认首选**，做"Top5图片核心卖点提取""竞品主图归纳""产品摄影参考"这类需要实际看图的分析时用这个 |
| ② 备选 | Brightdata `scrape`/`data-feeds`（brightdata-plugin） | **需要** `bdata login` 授权，本机常见未配置 | 结构化页面数据，含图片URL | ①不可用时才试；先跑 `bdata zones` 确认已登录，未登录不要空等，直接判定不可用转③ |
| ③ 兜底 | 本会话内置浏览器工具（`mcp__Claude_Browser__*`，仅 Claude Code 环境自带） | 不需要额外配置，但**只在当前会话可用，员工本机环境不一定有** | 实时打开页面截图/读文本核验，可临时验证 | 仅用于本次会话内的快速核验，**不写进"可复现方法"**——写报告方法论时不能只写"用浏览器工具"，因为下一个人/下一台机器不一定有这个工具，必须落到①的脚本上才算「可复现」 |
| ④ 最后兜底 | 无法取得任何真实图片 | — | — | 如实标注「图片数据未取得，本节结论为文字证据驱动，非视觉证据」，**不得**编造图片内容或用"推断"含糊带过——推断和"没去查"是两回事，任何图片相关结论标"推断"前必须先证明已经试过①②③ |

**判定准据**：写"竞品图片样本不足"之前，先问自己一句——**跑过 `amazon_image_capture.js` 了吗？** 没跑过，不能写"不足"，只能写"本节未取图，下一轮请先跑该脚本"。

### 0.1 视频取数与逐帧读取（图片分析涉及视频时必做）

> 历史教训（2026-10-10 立）：模块 2 第一版把视频写成"占位未下载，未读"，因为脚本只统计视频占位数、不取视频本体。视频内容（画面、场景、是否有功效宣称）只能靠视频本体获取，**"视频占位数"不等于"视频已读"**。

1. **取视频**：`node amazon_image_capture.js --asins <ASIN列表> --video --frame-interval 3 --outdir <DATA>/images --out <DATA>/images/images.json`（脚本在 `2-竞品销售策略分析/amazon-review-insights/scripts/`）。`--video` 逐个点击图库里的视频缩略图，读取播放器加载的地址：mp4 直接下载为 `<ASIN>_videoNN.mp4`；HLS（`.m3u8`）只记录地址，不下载。输出 JSON 的 `videos` 字段记录每个视频的地址、本地路径与抽帧列表。
2. **抽帧依赖 ffmpeg**：本机 PATH 有 `ffmpeg` 即可。没有时执行 `pip install imageio-ffmpeg`，再把环境变量 `FFMPEG` 设为它的 ffmpeg 可执行文件路径。帧保存在 `<DATA>/images/frames/`，文件名 `<ASIN>_videoNN_001.jpg` 起。
3. **逐帧读取**：用 Read 工具逐张看帧。每帧记录：时间点（第 N 帧约为 `(N−1) × 间隔` 秒）、画面主体（产品 / 人物 / 场景）、画面文字（品牌语、宣称）、是否有 AI 生成水印。**全部帧读完才算完成**，完成度 = 已读帧 ÷ 总帧数，必须 100%。
4. **写分析文件**：`<DATA>/images/analysis/video_<ASIN>.json`，字段 `{asin, videoIndex, url, frameInterval, frames:[{t, scene, text, product}], watermark, summary}`。
5. **口径限制（写报告时必须标注）**：抽帧间隔 3 秒时，3 秒内的快速切换会漏掉；无字幕时不能推断口播内容，只能写画面；HLS 版本未取时要写明；视频结论以画面为准，不写"口播称…"，除非拿到了字幕。
6. **验收**：`videos` 里每个 `localPath` 都要有对应的 `analysis/video_<ASIN>.json`，帧数与 `frames` 数组一致；缺一个就写明缺哪个。

**工具已验证**（2026-10-10，本品与 Pure Instinct 实跑）：点击视频缩略图后，播放器的 `currentSrc` 为 480p mp4 直链，约 9–12 MB；ffmpeg 通过 `imageio-ffmpeg` 可用。

## 一、主图标准（强制，不合格即红牌）

| 项目 | 合格线 | 不合格典型 |
|---|---|---|
| 背景 | **纯白底**（RGB 255,255,255），无渐变、无场景、无纹理 | 灰底、品牌色块、带道具背景 |
| 产品占比 | 产品主体占画面 **≥ 85%**，四周留白均衡 | 主体过小、偏左、被边框切割 |
| 文字/Logo | **无任何文字、水印、Logo、促销标**（含数量、天数、认证标） | 图上写 "2 Pack"、"Best Seller" |
| 边框 | 无边框、无圆角遮罩、无阴影描边 | 加了白色描边或圆角底 |
| 分辨率 | 最长边 **≥ 1000px**（建议 1600px），满足放大镜缩放 | 500px 缩略图、模糊 |
| 比例 | **正方形 1:1** | 长方形、被裁切变形 |
| 呈现 | 完整单品正面展示，无包装盒（除非盒即产品）、无模特手持遮挡 | 用外盒当主图、手遮住半边 |
| 角度 | 标准正面平视，不透视畸变 | 俯拍 45° 导致变形 |

> 主图只要命中任一红牌项，8 维「图片」维度该项直接判 **0 分**，不进入加权。

## 二、附图标准（6 类，按需覆盖）

附图共 6 类，每类有各自合格线。**8 维「图片 /15」的「有信息图 / 有场景图 / 有尺寸参照 / 有视频」四项，对照本表逐条确认。**

| 类型 | 合格线 | 用途 |
|---|---|---|
| **信息图** | 单图只讲 1–2 个卖点；图标/箭头清晰；文字 ≤ 主图体量；不堆参数表 | 快速传达核心差异 |
| **场景图** | 真实使用场景（车内角落/桌面/随身）；光线自然；不与主图场景重复 | 唤起使用想象 |
| **尺寸参照图** | 含硬币/手/尺子/真人对比，标注具体尺寸（cm/inch）；不靠目测 | 降低"比想象中小"差评 |
| **卖点/功能图** | 放大局部（木盖纹理/卡扣/接口）；对应一条差评疑虑或五点 | 解答购买疑虑 |
| **对比图** | 本品 vs 竞品**同框同角度同背景**；不贬低对方、不误导比例 | 凸显优势 |
| **套装/变体图** | 展示全部颜色/香味/数量；色卡对齐 | 降低变体选择成本 |

> **数量门槛**：主图 + 附图 **≥ 7 张** 才算图片维度满分项达标（与 8 维 rubric 一致）。

## 三、视频标准

| 项目 | 合格线 |
|---|---|
| 首帧 | 必须为清晰产品画面（非黑场/非文字封面） |
| 时长 | 6–30 秒为主，信息密度高 |
| 比例 | 9:16 或 1:1，移动端竖屏优先 |
| 内容 | 前 3 秒亮出产品+核心场景；不堆功能列表 |

> 视频本体的取法、抽帧与逐帧读取流程见本文件「零、取数方法 · 0.1」。视频判定以抽帧画面为准，抽帧间隔须写入报告口径。

## 四、A+ 内容图标准

| 项目 | 合格线 |
|---|---|
| 品牌故事模块 | 有品牌起源/价值观图，非单纯产品堆砌 |
| 对比图模块 | 同维度并排（功能/规格/适用场景），不贬低 |
| 场景模块 | 高清拍摄、风格统一、全图对焦清晰 |
| 技术质量 | 高分辨率、打光正确、无拉伸变形 |

> A+ 图不计「白底」强制，但**禁止文字过载与误导性对比**。

---

## 五、禁止项（红牌，任何图片命中即不合格）

1. 主图非纯白底（灰底/场景底/品牌色块）
2. 图上叠加任何文字、Logo、促销标、认证标
3. 误导性缩放（小物放大显得很大 / 大物缩小显得便携）
4. 用外包装盒充当主图（盒即产品除外）
5. 含水印、边框、圆角遮罩、阴影描边
6. 透视畸变导致产品变形
7. 对比图贬低竞品或篡改比例
8. 分辨率不足导致放大镜不可用（< 1000px 最长边）

## 六、判定流程（怎么用）

```
Step 1  拿到图片（主图 + 附图 + A+ 图 + 视频）
Step 2  主图逐条过「一、主图标准」→ 任一红牌即主图 0 分
Step 3  附图按「二」6 类逐类核对 → 标记 有/缺/不达标
Step 4  A+ 图过「四」、视频过「三」
Step 5  输出《图片合规表》（模板见下）
```

**产出物模板**：

```markdown
## 图片合规表 —— [ASIN / 产品名]

| 项目 | 主图 | 信息图 | 场景图 | 尺寸参照 | 卖点图 | 对比图 | 套装图 | 视频 | A+ |
|------|------|--------|--------|----------|--------|--------|--------|------|-----|
| 合格 | ✅/❌ | ✅/❌ | ✅/❌ | ✅/❌ | ✅/❌ | ✅/❌ | ✅/❌ | ✅/❌ | ✅/❌ |

**主图红牌项**：[无 / 第 X 项]
**图片维度得分（/15）**：[按 8 维 rubric 计]
**待补图**：[类型列表]
```

## 七、与其它规则的关系

| 规则 | 关系 |
|---|---|
| `竞品判定标准.md` | 对比图里的「竞品」必须先过竞品门槛，不能拿非竞品做对比图 |
| `深度分析层.md` | 图片维度结论需标口径（主图合规率/附图覆盖率），样本不足标低置信 |
| `交叉验证规则.md` | 「本品主图优于竞品」类结论须双源（本品图 + 竞品图同框核对），不可仅凭文字描述 |

> ⚠️ **本规则是 8 维「图片 /15」维度的唯一判定依据。** 任何图片相关 skill 不得自行定义图片合格线，改动只在本文件，全库生效。
