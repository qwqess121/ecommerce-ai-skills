# 模块二：竞品销售策略分析

> 本文件是给人看的目录说明，不是可调用的 skill。每个子目录下的 SKILL.md 才是实际工作流。

## 这个模块解决什么问题

拿到产品之后（不管是模块一刚定下的新品，还是已经在卖的老品），摸清楚这个产品所在的战场——竞品是谁、怎么定价、评论里骂什么夸什么、关键词分布在哪、卖家背景如何。这个模块**不产出Listing也不产出广告结构**，产出的是纯情报，直接喂给模块三（拿去改Listing）和模块四（拿去配广告）。

10个skill基本是**并行的情报采集矩阵**，不是严格的先后顺序——你可以只跑其中1-2个解决具体问题，也可以全跑一遍做完整竞品画像。

## 详细清单

### amazon-competitor-analysis — 全维度竞品分析
**定位**：一次性、全方位地把几个指定竞品拆开对比，是这个模块里信息密度最高的入口技能。
**输入**：竞品ASIN列表，或产品类目关键词
**工作流**：
1. 竞品数据收集——自动发现竞品ASIN，拉取Listing、价格、BSR、评论、广告可见度数据
2. 多维比较分析——构建特征对比矩阵，分析价格-价值定位、客户满意度差距、市场份额指标
3. 战略建议生成——输出定价优化机会、Listing改进优先级、产品差异化策略、营销定位角度
**MCP工具**：SIF `market_discover_competitors`（自动发现竞品ASIN）；卖家精灵 `asin_competitor`（竞品详情对比）、`asin_detail`（逐个竞品价格/BSR/评论/评分）、`traffic_keyword`（竞品流量关键词）、`review`（竞品评论数据）；SIF `ops_get_listing_keyword_distribution`（竞品关键词分布）；Brightdata `competitive-intel`（抓竞品Listing全文：标题/五点/描述/A+）
**输出**：竞品性能矩阵表（价格/评分/评论数/优劣势对比）+ 战略建议 + 行动清单

### amazon-competitor-monitoring — 竞品动态监控
**定位**：不是一次性分析，是持续盯着确定的竞品，抓变化（价格降了、库存断了、新品上了）。
**输入**：竞品ASIN或产品类目，支持12个亚马逊站点
**工作流**：
1. 识别竞品——用类目关键词搜索，提取Top竞品ASIN
2. 基线数据采集——收集当前价格、BSR、评分、库存状态作为基线
3. 历史背景研究——查价格历史、新品发布模式、评论投诉的时间线
4. 生成竞品分析报告——把变化综合成可执行洞察，而不是一堆原始数据
**MCP工具**：卖家精灵 `asin_sales_trend`（BSR/价格历史趋势）、`asin_coupon_trend`（促销变化监控）、`keepa_info`（价格历史曲线）；Brightdata `competitive-intel`（定期抓竞品页面变化）
**输出**：价格情报表 + 库存可用性表 + 绩效指标表 + 市场机会分析（即时行动+战略洞察+推荐监控告警项）

### amazon-keyword-research — 关键词研究与市场机会分析
**定位**：从种子词出发，挖出一整套长尾词并按机会大小排序，是关键词类skill里覆盖面最广的一个。
**输入**：种子关键词，站点（默认US，支持12站）
**工作流**：
1. Autocomplete数据采集——从Amazon自动补全API获取100-200个长尾词（前缀+字母扩展）
2. 竞争分析——搜索竞品数量、价格区间、平均评分、头部品牌
3. 季节性检查——查过去12个月的搜索趋势
4. 综合报告——合并所有数据，按购买意图给关键词分组，计算1-10分的市场机会评分
**MCP工具**：卖家精灵 `keyword_miner`（批量挖词）、`keyword_research`（搜索量+竞争度数据）、`google_trend`（替代web_fetch查Google Trends）；SIF `market_get_keyword_demand`（ABA级别搜索量）；原有的autocomplete脚本作为补充保留
**输出**：长尾关键词列表（按购买意图分类）+ 竞争格局表 + 季节性趋势 + 机会评分（1-10分及分项说明）

### amazon-keyword-tracker — 关键词排名实时监控
**定位**：盯着一批目标关键词，看自己的排名有没有变化，以及排名变化跟流量/转化的关联。
**输入**：目标关键词列表 + 产品ASIN
**工作流**：
1. 关键词监控系统搭建——部署实时排名追踪（自然/广告/精选内容三种排名）、竞品识别、多设备多站点监控
2. 告警系统与绩效关联分析——配置排名变化/竞品威胁/SERP变化告警，建立排名-流量-转化-收入的关联分析
3. 策略优化与竞品响应——基于监控数据自动生成优化建议，部署竞品反击方案，建立持续改进循环
**MCP工具**：SIF `ops_get_listing_keyword_distribution`（当前关键词排名分布）、`ops_get_listing_traffic_overview`（关键词→流量→转化的关联数据）；卖家精灵 `traffic_keyword`（竞品关键词排名对比）
**输出**：关键词排名仪表板（当前位置/变化/告警）+ SERP分解树 + 竞品位置追踪表 + 绩效分析 + 优化建议

### amazon-rank-tracker — BSR排名追踪
**定位**：跟keyword-tracker类似但视角是BSR排名而不是关键词排名，同时深挖A9算法的排名因素。
**输入**：产品ASIN + 目标关键词组合
**工作流**：
1. 全面排名分析与基线评估——分析当前排名建立基线，竞品对标，评估排名因素（相关性/转化/客户满意度/权威度），关键词优先级排序
2. 系统监控与绩效关联——部署排名追踪+告警，分析排名变化的原因（算法/竞品/优化），关联排名与流量/转化/收入
3. 优化策略与排名恢复——制定目标优化策略，A/B测试，建立排名保护和算法适应框架
**MCP工具**：卖家精灵 `asin_sales_trend`（排名历史）；SIF `ops_get_listing_keyword_distribution`（关键词排名）、`market_get_keyword_root_competitors`（竞品排名对标）
**输出**：排名分布（Top3/Top10/Top20/未排名）+ 关键词详细排名表（含变化/搜索量/流量占比）+ A9排名因素评分 + 竞品排名对标 + 改进策略+时间线 + ROI分析

### amazon-review-analyzer — 评论深度分析
**定位**：不管自己产品还是竞品，把评论文本转化成结构化的产品洞察，而不是人工一条条翻。
**输入**：产品ASIN或类目关键词
**工作流**：
1. 评论数据收集——采集各星级评论样本，提取主题和语言模式
2. 情感与主题分析——按产品功能做情感评分，投诉频率+严重度排名，功能需求识别，竞品提及分析
3. 可执行洞察生成——产品改进优先级、营销信息机会、竞品定位角度、质量问题缓解策略
**MCP工具**：卖家精灵 `review`（结构化评论数据：星级/日期/内容）；Brightdata `scrape`（批量抓取评论页面补充）
**输出**：情感概览（正面/负面主题）+ 投诉分析表（类别/频率/严重度/影响/客户原话）+ 功能需求排序 + 竞品情报（替代品/转换触发/竞品优势）+ 行动优先级（立即修复/产品开发/营销机会）

### amazon-brand-analytics — Brand Analytics数据解读
**定位**：专门解读需要品牌注册权限才能拿到的Brand Analytics数据（SFR、Market Basket、Item Comparison），找出普通竞品分析看不到的机会。
**输入**：Brand Analytics导出数据，或通过卖家精灵ABA相关接口自动获取
**工作流**：
1. 数据准备——获取SFR（90天Top100-200关键词）、Market Basket（6-12个月共购数据）、Item Comparison（竞品对比数据）
2. 模式识别——SFR识别高搜索低点击份额的机会词+季节性趋势；Market Basket识别共购率超过25%的捆绑候选；Item Comparison分析客户决策因素排序
3. 战略综合——把洞察转化为可执行建议（广告/捆绑/品类扩展/定价方向）
**MCP工具**：卖家精灵 `aba_research_weekly`（周度ABA搜索频率排名）、`aba_research_monthly`（月度）、`aba_research_trend`（趋势分析）
**输出**：关键词机会差距表（搜索排名/你的点击份额/类目平均/机会评分）+ 交叉销售机会表（共购率/收入机会/建议）+ 竞品定位（客户考虑因素排名+你的优劣势）+ 30天/Q4/年度战略建议

### amazon-seller-analytics — 卖家画像分析
**定位**：不看单个产品，看整个竞品卖家的运营打法——他的品类布局、估计收入、增长模式。
**输入**：卖家名称/品牌名，或类目
**工作流**：
1. 卖家识别与基础情报——搜索卖家店铺、反馈评分、账号年龄、活跃产品数、主营品类
2. 产品组合深度分析——分析品类多元化程度（专注/分散/散乱）、SKU深度、价格架构（入门/核心/高端）
3. 营收估算——通过BSR估算法、评论速度分析法、市场份额法三种方式估算月/年收入
4. 增长策略分析——追踪产品上新时间线，分析垂直/水平扩展模式，品牌演进路径
5. 竞争定位分析——评估差异化策略（创新/品质/性价比/利基专家）、客户获取方式
**MCP工具**：卖家精灵 `market_seller_concentration`（卖家市场占比）、`asin_detail`（逐产品BSR/评论/价格）、`competitor_lookup`（卖家信息查询）
**输出**：卖家概览（品牌/年限/评分/营收估算）+ 产品组合分析（品类分布树+策略）+ 收入分解表 + 增长轨迹时间线 + 成功因素+潜在弱点 + 多卖家对比表

### amazon-price-tracker — 价格监控与竞争定价情报
**定位**：专注价格和Buy Box动态，不管Listing内容和评论，只盯钱和归属权。
**输入**：产品ASIN列表 + 竞品ASIN
**工作流**：
1. 价格监控与市场分析搭建——部署实时价格追踪，建立Buy Box追踪+资格分析，配置多站点监控
2. 动态定价策略与竞品响应——开发基于竞品/库存/业务目标的定价规则，配置自动响应协议+利润保护，实施Buy Box优化策略
3. 战略分析与绩效优化——关联定价策略与销售/利润指标，跨组合定价优化，部署预测性定价分析
**MCP工具**：卖家精灵 `keepa_info`（历史价格曲线）、`asin_coupon_trend`（价格+促销变化）；Brightdata `competitive-intel`（实时竞品价格抓取）
**输出**：价格追踪表（你的价格/最佳竞品/价差/Buy Box状态/变化/告警）+ Buy Box绩效分析（赢率/收入/资格因素评分）+ 竞品定价策略分析 + 动态定价规则框架 + 弹性分析 + ROI投影

### amazon-repricing-strategy — 调价策略与Buy Box优化
**定位**：比price-tracker更进一步，直接给出一套可执行的调价规则，而不只是监控数据。
**输入**：卖家产品目录 + 成本数据（COGS），建议配合领星ERP
**工作流**：
1. 市场分析与竞争情报——竞品定价格局映射，Buy Box获胜因素分析，价格弹性评估，机会与弱点识别
2. 定价策略与规则开发——按产品分层（高竞争/中等/低竞争）创建定价规则，设定利润保护红线，设计促销/季节性调整框架
3. 实施与优化——评选调价工具（对比矩阵），配置自动化工作流+安全控制，监控绩效指标并持续优化
**MCP工具**：卖家精灵 `asin_detail`（竞品当前价格）、`keepa_info`（价格弹性分析）；领星ERP `search`（COGS+固定成本→算最低利润率红线）
**输出**：竞品格局表（市场份额/价格定位/Buy Box赢率）+ 分层定价策略（高/中/低竞争）+ 定价规则伪代码（Buy Box追踪/利润保护/库存联动/速度调整）+ 调价工具对比矩阵+推荐 + 利润保护框架（三层保护）+ 实施时间线（4阶段8周）+ ROI分析

## 内部串联逻辑（举例说明）

假设你要对一个已经上架3个月的产品做一次完整的竞争力体检：

1. 先用 `amazon-competitor-analysis` 做一次全面扫描，确定3-5个主要竞品
2. 针对这几个竞品，开 `amazon-competitor-monitoring` 长期盯着他们的价格/库存/新品动态
3. 同时用 `amazon-keyword-research` 摸清整个关键词版图，再用 `amazon-keyword-tracker` + `amazon-rank-tracker` 盯自己产品的实际排名表现
4. 用 `amazon-review-analyzer` 挖自己和竞品的评论，找产品/Listing的可乘之机
5. 如果有品牌注册权限，补一次 `amazon-brand-analytics`，找关联购买和搜索排名的具体缺口
6. 想深挖某个头部竞品的整体打法，单独用 `amazon-seller-analytics` 做卖家级别分析
7. 定价相关问题单独走 `amazon-price-tracker`（监控）和 `amazon-repricing-strategy`（落地规则）

这个模块的所有产出——竞品数据、关键词缺口、评论痛点、定价情报——最终分别交给模块三改Listing，交给模块四配广告结构。

## 竞品对比与评分（新增，2026-09-20）

本模块所有竞品分析必须先按 `../_references/竞品匹配与评分规则.md` 第一节筛出"属性一致+形态一致+场景一致"的可比竞品，再打分，不能拿泛泛的同类目产品凑数：

- `amazon-competitor-analysis` 的对比矩阵，每一行必须是已过滤的可比竞品，被排除的候选要写排除原因
- 所有涉及"高于/低于类目均值"的表述，一律换成"行业对标百分位"（第X名/共N个，Top Y%），公式见评分规则第二节
- 差评问题优先级不再用模糊的"重要/一般"，改用"受影响比例×严重度"的量化公式（评分规则第三节）
- 定价类结论（`amazon-price-tracker`/`amazon-repricing-strategy`）必须结合领星ERP真实成本，卖家精灵的类目profit字段只做背景参考

## 评判标准速查表

| 检查项 | 数据来源 | 判定阈值 |
|---|---|---|
| 竞品价格威胁 | 卖家精灵 `keepa_info`/`asin_detail` | 竞品降价超过10%且自己利润率承受不住时，判定需要响应（跟价或差异化，不盲目跟到亏损） |
| 关键词机会评分 | SIF `market_get_keyword_demand` | 搜索量高但自己排名>页2的词，判定为优先优化对象 |
| 评论情感健康度 | 卖家精灵 `review` | 某类投诉主题占比超过30%，判定为结构性问题，需转交模块一/供应链，不只是靠营销掩盖 |
| 品牌集中度风险 | 卖家精灵 `market_brand_concentration` | Top3份额>50%的类目，判定不适合正面价格战 |
| Buy Box健康度 | 卖家精灵 `asin_detail`+`keepa_info` | 赢率<80%且价格具竞争力时，判定问题在绩效指标而非定价（转交模块六 `amazon-buy-box`） |
| 调价利润红线 | 领星ERP 真实COGS | 任何调价规则不得让净利率跌破安全线（建议5%以上，以实际财务模型为准） |

## MCP 集成程度

这是全套60个skill里MCP集成程度最高的模块——10个全部接入了卖家精灵/SIF/Brightdata，给一个类目关键词或ASIN就能自动拉真实数据，不需要手动输入产品信息。只有 `amazon-repricing-strategy` 因为要算真实利润率下的最优定价，需要配合领星ERP的真实成本数据才能出精确的定价红线，否则只能给出定性建议。
