# 输出格式强制规定（1–5 模块统一适用）

> 本文件是所有模块报告的唯一格式依据。模块 1–5 的 SKILL 与编排器（ORCHESTRATOR）都必须引用本文件。
> 参考样例：Xk3D（PUREU 信息素香水）与 Vy3j（HoogaLife 悬挂香）两份在线报告。

## 1. 交付物

- 每次分析的最终交付是**一个单页 HTML 报告** `report.html`，由 `共享规则/在线报告生成/` 工具生成。
- 报告包含：总览（m0）+ 模块 1–5，共 6 个页面。页序固定，不得增删。
- 不允许交付纯 Markdown 或纯文字版报告作为最终成品。Markdown 只作为中间产物（`模块N-*.md`）。

## 2. 目录与文件

报告目录内必须包含：

| 文件 | 来源 | 说明 |
|---|---|---|
| `模块1-产品开发-<ASIN>.md` … `模块5-内容生产-<ASIN>.md` | 模块分析写作 | 5 份，文件名前缀 `模块N-` 决定顺序 |
| `overview.json` | 手写 | 页面标题、品牌信息、五个模块的导航文案 |
| `overview.html` | 手写 | 总览页正文（KPI、模块卡片、关键发现、已知矛盾、取数说明） |
| `sections.json` | `convert.js` 生成 | 不手写 |
| `report.html` | `build.js` 生成 | 最终成品 |

## 3. 每个页面的必备结构

每个模块（m1–m5）与总览（m0）页面都必须包含：

1. **H1 标题**：模块标题原文（模块四固定写 `模块四·广告策略分析 —— <本品名>`）。
2. **引导块** `<div class="guide">`：三行，依次为 `取数概览`（取数时间、数据窗口、数据时效）、`取数对象`（标的与对比对象清单）、`本页目录 · 点击直达`（列出本页全部 H2）。引导块内 ASIN 写纯文本（不写 `[文字](url)` 链接语法），由构建脚本自动加链接。
3. **分析区块**：每个 H2 下至少一个 `**小结** —— …` 区块。**同一类区块在全部报告中颜色一致**，颜色由模板按段首加粗标签自动套用：

   | 段首标签（加粗） | 区块颜色 | 用途 |
   |---|---|---|
   | `**小结** —— …` | 蓝紫（summary） | 本节收尾的整体结论，每个 H2 一个 |
   | `**发现** —— …` | 琥珀（finding） | 本节真正需要读者注意的一条发现 |
   | 段首标签含 `修正`、`限制`、`缺口`、`未完成`、`风险`、`警告` | 红橙（warning） | 修正声明、已知限制、缺口、风险 |

   - **不写 `结论`、`依据`、`含义与置信度` 等三段式标签**，也不写解释这些标签的说明句。正文直接写判断和数字，读者不需要读"这段是结论还是依据"。
   - 数字的来源用表格下方的一行 `来源：…` 说明（工具名与字段），不另起"依据"段落。
   - 不要自己加 HTML 颜色或 class，颜色只由模板按标签决定；想换颜色只改 `template.html` 的 `BLOCK_RULES`，全部报告同时生效。
   - 解释要克制：每个 H3 写到能看懂即可，不写"本段的置信度为中"之类的套话；置信度只在数据确实有口径问题时用一句话点明。
4. **表格**：`<div class="tablewrap"><table>…</table></div>`，表头 `<thead>`，数字列 `class="num"`，表后紧跟 `<p class="src">来源：…</p>`。
5. **ASIN 链接**：正文与表格中出现的每个 ASIN 必须是 `<a class="asin" href="https://www.amazon.com/dp/<ASIN>" target="_blank" rel="noopener">`。
6. **翻页导航**：由 `build.js` 自动添加，模块作者不需要写。

模块五额外要求：提示词必须放在 `<div class="prompt">…</div>` 中，不得留方括号占位符。

## 4. 对比表（方向 A/B、候选方案）

- 使用 `<div class="tablewrap cmp-wrap">`。
- **凡是对比、并排、多方案、时间计划，一律用表格，不得用段落或列表代替**：包括"A 与 B 的对比"、"垂直 vs 扩展"、"候选方案的需求/竞争/判定"、"执行时间线（第一个月/第二个月/第三个月）"、"BS100 等门槛的横向对标"。段落只用于单一结论的叙述。
- 表格的行列要完整：每格有内容，写不出就填"未取"并说明原因；表下方用 `<p class="src">来源：…</p>` 给出工具与字段。
- 判定行使用优先级标签：`<span class="pri pri-p0">优先</span>`、`pri-p1` 跟进、`pri-p2` 观察/备选、`pri-p3` 远期、`pri-no` 不做。

## 5. 禁止事项

- 占位符：`{{…}}`、`[SECONDS]`、`[confirm …]` 等一律不得出现。缺数据写 `未取（原因：…）`，原因必须具体。
- 过程用语：正文可见文字不得出现 本轮、审计、矛盾、修正版、前一版、我们之前、自查、如实列出、如实公开、重跑。
- 数字不可追溯：每个数字必须能对应到数据来源（工具名与字段）。

## 6. 交付前核对

按 `共享规则/报告格式/格式检查清单.md` 逐项核对。未通过项必须修正后再交付，不得以"样式问题"为由跳过。
