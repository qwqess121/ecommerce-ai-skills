# Skill: VOC 消费者洞察（v6.2 补充模块）

> **权威来源**: SKILL.md §七 7.4 Section 2.3。本文件是 08-合规评论诊断.md 的补充，提供评论文本深度挖掘的执行细节。

## 定位

**不单独成节**。当评论原文可用时，为 Section 2.3 提供更深入的消费者洞察数据；当不可用时，08 已有的统计数据对比足够。

## 评论数据三级降级（必须执行）

### FastMoss API 限制

| 评论数量级 | API 表现 |
|-----------|---------|
| >500 条 | 正常返回评论原文 |
| <500 条 | 大概率返回 0 条 |

### 降级路径

```
Level 1: FastMoss product_review_list（不传 time_range，取全量）
├── 返回 >0 条 → 可做全量文本分析
│
└── 返回 0 条 → Level 1.5: TikTok 爬虫
    ├── 执行: python scripts/tiktok_review_scraper.py {product_id}
    ├── 输出: 3 条评论原文 + 全量评分分布(1-5星)
    ├── 分析: 用 3 条原文做有限文本分析（标注"基于 3 条样本"）
    │         用全量评分分布做量化对比
    │
    └── 爬虫失败或无评论 → Level 2: detail_info 统计数据
        ├── 数据: product_detail_info 的 product_rating + review_count
        ├── 分析: 仅量化对比，跳过文本分析
        └── 标注: "评论文本不可用，基于统计数据分析"
```

每个产品（本品+竞品）独立降级，互不影响。

## 有评论原文时可补充的分析

以下内容在 Level 1 或 Level 1.5 时可追加到 Section 2.3：

1. **好评卖点提取**：从 4-5 星评论提取高频正面关键词
2. **差评痛点提取**：从 1-3 星评论提取问题主题 + 可解决性评估
3. **购买动机分析**：消费者提到的购买原因（价格/达人推荐/外观/场景）
4. **使用场景提取**：实际使用场景 + 频次
5. **Listing 一致性验证**：标题声明的卖点 vs 评论实际反馈是否一致

Level 1.5 时标注"基于 3 条样本"，结论标注局限性。

## Level 2 输出范围

当所有产品均为 Level 2（无评论原文）：
- 仅输出评论数/评分的量化对比（已在 08 的评论概览对比中覆盖）
- 跳过全部文本分析
- 标注"评论数积累至 500+ 后可重新运行获取完整 VOC 洞察"

---

## 固定输出格式（按数据级别分）

### Level 1（API 全量评论可用）追加输出：

| 分析项 | 输出格式 |
|--------|---------|
| 好评卖点 TOP5 | 关键词 + 出现频次 + 示例原文 |
| 差评痛点 TOP5 | 问题主题 + 频次 + 严重程度(高/中/低) + 本品可解决性 |
| 购买动机 | 动机类型 + 占比（如"达人推荐40%, 价格30%, 外观20%, 其他10%"） |
| 使用场景 | 场景 + 提及次数 |
| Listing一致性 | 标题声明 vs 评论实际反馈 的匹配/不匹配项 |

### Level 1.5（爬虫 3 条样本）追加输出：

- 同 Level 1 的表格结构，但每项标注"基于 3 条样本"
- 结论标注局限性："样本量有限，仅供参考，不宜做强结论"
- 全量评分分布可做量化对比（这部分数据是完整的）

### Level 2（仅统计值）输出：

- 不输出任何文本分析
- 仅在 08 的评论概览对比表中体现评分/评论数
- 标注"评论数积累至 500+ 后可重新运行获取完整 VOC 洞察"

### 输出规范

- 用精简 Markdown，禁止输出 HTML 标签和 CSS 类名
- HTML 在最终步骤统一生成
- 不重新调用 API，使用阶段 B/D 已提取的精简字段
