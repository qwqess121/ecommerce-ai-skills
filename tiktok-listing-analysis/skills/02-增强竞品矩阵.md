# 02 - 竞品矩阵 7+3 选取与取数（v6.2）

> **对应 SKILL.md 阶段 C（L3 大盘）+ 阶段 D（竞品选取与取数）**
> 本文件是操作步骤的展开说明，字段与规则以 SKILL.md 为准。

## 目标

1. L3 榜单 1-50 名全量取回 → 计算 L3 大盘指标 + 提取 TOP20 标题词源
2. 7+3 选品：前 7 按自然排名，后 3 为同形态产品（AI 看图判定）
3. 对 10 款竞品逐个取数 → 填满 16 行 × 12 列矩阵

---

## 阶段 C：L3 大盘取数

### C1. 榜单分页全取（5 页 × 10 条 = 50 条）

```
product_rank_top_selling({
  category_id: L3_category_id,    ← 从阶段 A 获得
  date_type: "week",
  date_value: "YYYY-ww",          ← 必须为已结束的完整周
  page: 1~5, pagesize: 10
})
```

每条提取：`product_id / title(完整) / cover_url / floor_price+ceiling_price / commission_rate_percent / period_gmv / period_units_sold / total_gmv / total_units_sold / units_sold_growth_rate_percent / launch_date / shop.shop_name`

> ⚠ `pagesize` 上限就是 10，**必须分 5 页**取全 50 条
> ⚠ `date_value` 传当前未结束的周会返回空数据

### C2. L3 大盘指标加总 → 概览 ② 固定输出

从 50 条数据逐条计算（公式见 SKILL.md §四），产出概览 ② 的 8 项信息卡：

| # | 信息卡标签 | 公式/来源 |
|---|-----------|---------|
| 1 | L3 TOP10 周GMV合计 | Σ period_gmv(1→10) |
| 2 | L3 TOP50 周GMV合计 | Σ period_gmv(1→50) |
| 3 | L3 TOP10 周销量合计 | Σ period_units_sold(1→10) |
| 4 | 头部集中度（TOP10/TOP50） | TOP10 GMV ÷ TOP50 GMV |
| 5 | L3 在榜商品数 | 固定写 500+ 或实际数量 |
| 6 | L3 主流价格带 | TOP10 的 floor_price min ~ ceiling_price max |
| 7 | 本品 L3 类目排名 | detail_info.category_sales_rank |
| 8 | 占 L3 TOP50 大盘份额 | 本品周GMV ÷ TOP50 GMV |

表后接 callout：解释为什么用 L3 不用 L1 + 由集中度推出的可执行结论

### C3. TOP20 标题词源

从排名 1-20 的产品标题中提取关键词词频（用于 Section 2.1 关键词诊断）。
- 先剔除明显错分类目的产品（如车香薰榜出现男士发胶）
- 记录实际参与统计的产品数（如"TOP20 去除 1 条错分，实际 19 条"）

### C4. 竞品候选池

榜单 1-50 名的 `cover_url` 全部保留，用于阶段 D 的 AI 看图选品。

> **★ `market_category_analysis` 已停用** — 它只支持 L1，L1 含轮胎车灯等无关品类，算出的市占率失真到没有决策价值。全部改用 L3 榜单加总。

## 阶段 D：7+3 竞品选取

### D1. 选取规则

| 席位 | 来源 | 选取标准 |
|------|------|---------|
| 第 1-7 席 | 榜单自然排名 1-7 | 直接入选 |
| 第 8-10 席 | 榜单 8-50 名 | **与本品外观形态一致** + 按近7天销量取前 3 |

不足 3 个同形态 → 放宽到 8-100 名 → 仍不足则**如实写明检索范围与结果，不得凑数**。

### D2. AI 看图定形态（不可省略）

```
把候选 cover_url 拼成一页本地 HTML → Browser pane 打开 → AI 截图识别，逐张比对外观
```

**操作步骤**：
1. 用 50 条候选的 `cover_url` 生成一个 HTML 图片墙（每张图标注排名、标题、7天销量）
2. 用 Browser pane 打开该 HTML
3. AI 截图后逐张识别产品外观形态
4. 归类：圆柱坐杯架 / 挂绳挂件 / 出风口夹式 / 贴片 / 喷雾瓶 / 电子设备…
5. 只保留与本品**外观真正一致**的

> **实测教训**：关键词搜 "cup holder" 会漏掉不写形态词的同形态产品；而 R&W（821件/周）主图是挂绳款、JOYTUTUS（159件/周）是出风口夹式——只看标题会全判错。

### D3. 逐个取数

**对矩阵 10 款**（每款调用）：

| 工具 | 参数 | 提取字段 |
|------|------|---------|
| `product_detail_info` | product_id | title、floor_price、commission_rate、rating、review_count、category_sales_rank、launch_time、stock_count、cover_url |
| `product_overview` | product_id, time_range_days:28 | period_gmv、period_units_sold、video_gmv%、live_gmv%、product_card_gmv%、avg_video_play |
| `product_video_list` | product_id, time_range_days:**7** | 计算视频均播（Top 5 播放量均值）|

**对选定的 5 个对标竞品**，补充：

| 工具 | 参数 | 用途 |
|------|------|------|
| `product_creator_analysis` | product_id | 达人明细、per-creator GMV% |
| `product_sku` | product_id | SKU 阶梯对比（按需）|
| `product_review_list` | product_id（不传 time_range）| 评论交叉验证（按需）|

> ⚠ `product_video_list` 竞品用 **7 天**窗口（与本品 28 天区分），必须传 `time_range_days`

### D4. 形态生存力验证（逐款明细 + 4 项证据）

当同形态竞品 ≤ 3 款时，**禁止直接写"蓝海/差异化窗口"**，必须先输出详细数据再做判断。

#### D4a. 同形态产品逐款明细表（必须先输出）

在 4 项证据表之前，先输出一张逐款明细表，包含每个同形态竞品 + 本品：

| 列 | 说明 |
|----|------|
| 产品名+链接 | 可点击跳转 |
| 售价 | floor_price–ceiling_price |
| 周销量 | 近 7 天 |
| 周GMV | 近 7 天 |
| 累计GMV | total_gmv |
| 评分/评论数 | product_rating / review_count |
| 达人数 | linked_creator_count |
| 视频数 | linked_video_count |
| L3排名 | category_sales_rank |
| 上架时间（含已运营时长） | launch_time，括号注明"X个月" |
| 驱动方式 | AI 看图判定（被动挥发/电子喷雾/夹式等） |

末行为**合计/均值行**，最后一行为**本品对比行**（高亮）。

> **为什么要这张表**：之前只写"3 款合计 760 件"，读者无法判断哪款强哪款弱、价格带是否重叠、新品成长速度如何。逐款拆开后才能支撑后面 4 项证据的判断。

#### D4b. 4 项证据表

| # | 证据 | 回答模板（必须引用 D4a 表中的逐款数据） |
|---|------|---------|
| ① | 还在卖吗？ | **逐款列出**：Autrex 周销 X 件/$Y、Ceesooi 周销 X 件/$Y……合计 Z 件/$W |
| ② | 有新入场者吗？ | **逐款列出上架时间+当前排名+达人/视频数**：Autrex 2026-07 上架，2.5 个月冲到 L3 #251，8 达人/67 视频 |
| ③ | 零销量 = 没需求还是没推广？ | 零销产品达人数/视频数均为 0 → 未被推广；**对比有销量产品的达人/视频规模** |
| ④ | 赢家长什么样？ | TOP 同形态产品的共同特征 vs 本品差异，**引用具体售价区间和驱动方式** |

> ⚠ 4 项证据中的数据**必须与 D4a 明细表完全一致，且拆到单个产品**（不能只写合计）。

4 项证据综合后得出**分层结论**：形态本身是否被市场验证 + 本品子形态是否有成功先例。

### D5. 僵尸链接剔除

近 7/28/90 天销量均 0、达人数/视频数 ≈ 0 → 不计入竞品对比，但报告注明数量。

## 固定输出格式（换任何产品都必须按此结构输出）

### 矩阵表（转置：维度做行、竞品做列）

**≥17 行 × 12 列**（产出 → 报告 Section 1.1）：

**行（固定顺序，不可调整）**：

| # | 行名 | 数据来源 | 备注 |
|---|------|---------|------|
| 1 | ★产品形态 | AI 看图判定 | 挂式/杯架式/出风口夹式/贴片… |
| 2 | ★驱动方式 | AI 看图判定 | 被动挥发/电子喷雾/手动喷雾… |
| 3 | 价格 | detail_info.floor_price–ceiling_price | 区间显示 |
| 4 | 佣金率 | detail_info.commission_rate_percent | X% |
| 5 | 周GMV | product_rank_top_selling.period_gmv | 已完成周 |
| 6 | 周销量 | product_rank_top_selling.period_units_sold | 已完成周 |
| 7 | 累计GMV | detail_info.total_gmv | 上架至今 |
| 8 | 评分 | detail_info.product_rating | X.X |
| 9 | 评论数 | detail_info.review_count | 整数 |
| 10 | 达人数 | detail_info.linked_creator_count | 累计 |
| 11 | 视频数 | detail_info.linked_video_count | 累计 |
| 12 | 直播场次 | detail_info.linked_live_count | 累计 |
| 13 | 运费 | detail_info.shipping_fee | $X.XX 或 免运费 |
| 14 | 到手价 | 售价+运费 | 派生 |
| 15 | SKU数 | detail_info.sku_count | 整数 |
| 16 | L3类目排名 | detail_info.category_sales_rank | #X |
| 17 | 上架时间 | detail_info.launch_time | YYYY-MM |

**列（12 列，固定顺序）**：
1. `#1` – `#7`：L3 榜单自然排名 1-7（列头标产品简称+链接）
2. `★同形态1` – `★同形态3`：从榜 8-50 筛出的同形态（绿色底色，列头标"★[名称] 榜#X"）
3. `TOP10 均值`：矩阵 10 款的均值（浅紫背景）
4. `★ 本品`：最右列（高亮行 accent-light 背景）

### 视觉标注规则
- 本品列：浅紫背景（accent-light）
- 同形态 3 席：绿色底色（green-bg）
- 各行最优值：加粗（`.best`）
- 低于均值的警告值：红色（`.ic-v.zero`）或橙色（`.ic-v.warn`）
- 每个产品名可点击跳转

### 矩阵下方固定 4 段内容（顺序不可调整）

1. **数据核验说明**（success callout）：取数日期 + API 来源 + 本轮修正项
2. **7+3 构成说明**（普通 callout）：前 7 席来源 + 后 3 席选取方法（含排除示例）
3. **竞争位置**（danger callout）：本品 vs 均值的关键指标差距
4. **★ 形态生存力验证**：
   - 4a 同形态逐款明细表（11 列，见 D4a）
   - 4b 4 项证据表 + 分层结论（见 D4b）

---

## TOKEN 优化

- 每个 API 调用完成后**立即提取必要字段，丢弃原始 JSON**
- 每个产品提取 ≤ 15 行
- 榜单 50 条数据只保留关键字段，不写入完整 JSON
- 全部用 **Markdown 格式**输出，不输出 HTML
