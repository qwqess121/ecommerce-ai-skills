# TikTok Shop Listing 诊断 + 竞品分析（v6.2）

## 这是什么

输入一个 TikTok Shop 产品链接/ID/关键词/店铺名，产出一份 **Listing 诊断 + 竞品分析** 报告（HTML，发布为在线 Artifact）。

**完整规则见 [SKILL.md](SKILL.md)**，该文件是唯一权威（与 `skills/` 子文件冲突时以它为准）。下面只列最容易踩坑的几条：

**报告结构（4 板块）**：★概览（含市场背景，按"维度由大到小"排）→ Section 1 TOP10竞品矩阵（含达人与内容）→ Section 2 Listing诊断 → Section 3 风险评估

**五条最关键的硬性规则**
1. **数据必须实取**：矩阵每个单元格都是当次 API 取值，核心行不允许 `≈`；类目排名/店铺GMV/售价等易变字段禁止沿用历史报告（实测曾出现排名差 700 名、店铺GMV差 130%、评论数估值差 13 倍）
2. **类目大盘一律 L3 口径**：`market_category_analysis` 只支持 L1（含轮胎车灯等无关品类，基数失真）已停用，改为 L3 榜单 1–50 名逐条加总
3. **竞品 7+3 选取法**：前 7 名按自然排名，后 3 席必须是**与本品同形态**的产品（从榜单 8–50 名中按近7天销量取前3）；**同形态判定由 AI 通过 Browser pane 逐张看主图判定**，不依赖标题关键词（只看标题会全判错）
4. **禁止把"同形态竞品少"写成"蓝海"**：必须先用 4 项证据证伪"死海"假设，并把"形态是否成立"与"本品子形态是否被验证过"分层表述
5. **评分只出数字**：`X/10`、`X/60`，不展示权重、公式、进度条

## 如何触发

用户给出 TikTok Shop 产品链接 / 产品ID / 关键词 / 店铺名时，读取 [SKILL.md](SKILL.md) 并**按 5 步全部执行**，产出 ★概览 + Section 1–3 的完整报告。禁止只出 Listing 诊断而漏掉竞品分析。

**反问逻辑**：没给产品信息 → 反问；给了非 TikTok Shop 链接 → 说明只支持 TK Shop；只给店铺名 → 先列 TOP 产品让用户选；只给类目词 → 问要整体格局还是具体产品。市场默认 US、竞品自动筛选，不反问。

## 数据源

- **FastMoss MCP**（主）：字段与调用规范见 SKILL.md §2.1 数据来源对照表；已知坑见 §2.4
- **Browser pane**：AI 通过截图识别主图判形态、看详情页图片质量（FastMoss 只给图片URL和数量，不判断内容）

## 输出

1. Step 1–4 用精简 Markdown 推进（MCP 原始 JSON 不写入上下文，只提核心字段，标题不截断）
2. Step 5 先出 Markdown 报告供用户确认 → 确认后生成 HTML → **发布为在线 Artifact 并回传链接**（更新时复用同一 URL）
3. CSS/HTML 结构从 [skills/12-统一报告格式.md](skills/12-统一报告格式.md) 加载，不重写；以 HoogaLife 2-Pack 报告 Artifact（ef4c6de9）为格式参照
4. 交付前逐条对照 SKILL.md §八 检查清单
