# 12 - 统一报告格式规范（v6.3 — Markdown 模板）

> **定位**: 报告 Markdown 结构模板。生成报告时**严格按本文件的 Markdown 结构**输出，确保每次输出内容完整一致。
> 冲突时以 SKILL.md 为准。
>
> **v6.3 变更**: 输出格式从 HTML 改为 Markdown（`.md`），发布为在线 Artifact。文件名 `report_{product_id}.md`。
> **★ 内容完整性参照**: HOOGALIFE 2-Pack 杯架式车载香薰报告。每一个板块的数据深度必须不低于该参照。

---

## 一、文件与发布规范

| 规则 | 说明 |
|------|------|
| 文件名 | `report_{product_id}.md` |
| 发布方式 | 通过 Artifact 工具发布 `.md` 文件 |
| 更新 | 复用同一 Artifact URL，不创建新链接 |
| 语言 | 所有标签、表头、分析文字使用中文 |
| 禁用泛化代号 | 不得出现 `本品`、`竞品A/B/C`——一律用具体简称 |
| 评分展示 | 只出 `X/10`、`X/60` 数字，禁止公式/权重/进度条 |
| 产品链接 | `[产品名](https://shop.tiktok.com/us/pdp/-/{id})` 可点击跳转 |

---

| 规则 | 说明 |
|------|------|
| 文件格式 | Markdown `.md`，**不输出 HTML** |
| 产品链接 | `[产品名](URL)` Markdown 链接格式 |
| 表格 | Markdown pipe table，宽表不需要 overflow 处理（Artifact 自动处理） |
| 趋势图 | 用表格替代 CSS 柱形图；如数据量大可只列周汇总 |
| 渠道分布 | 用表格 + 百分比数字，不用 CSS bar |
| 中文术语 | GMV→销售额可括注、Creator→达人、Product Card→商品卡 |
| 新旧对比 | 所有修改建议必须"优化前 / 优化后 / 变更依据"并排 |
| 评分 | 只出 `X/10` 与 `X/60`，无公式无权重 |
| 数据唯一出处 | 同一张数据表不得出现两次 |
| 字符数核对 | 标题优化后必须实际数出字符数 |
| 可量化承诺 | 需附"需真实测试后再上架" |

## 四、内容完整性检查清单（交付前逐条核对）

```
结构:
□ 4 板块齐全：概览 / S1矩阵 / S2 Listing诊断 / S3风险
□ 概览按 ①产品→②L3大盘→③店铺→④趋势→⑤MSKU→⑥竞品 顺序
□ 无泛化代号；无"不应出现"的板块

矩阵与竞品:
□ 矩阵 ≥16 行 × 12 列
□ 前两行为产品形态/驱动方式
□ 同形态逐款明细表（每款一行 + 合计行 + 本品对比行）
□ 4 项证据逐款拆解 + 分层结论
□ 达人流量对比表（多产品横向）
□ 达人明细逐人占比 + 合计行
□ 佣金策略 + 达人招募策略（全篇仅此一处）

Listing 诊断:
□ 评分总览 3 列表
□ TOP20 高频词分析表（含方法论 + 热度分级 + 同形态覆盖列）
□ 标题新旧对比 + 逐项变更依据
□ 商品描述诊断 ≥6 项检查 + 逐段新旧对比表
□ TK 官方 8 条图片规则判定
□ 竞品图片对比表
□ 图片逐张优化建议（5列不留空）
□ SKU 缩略图优化
□ 评论原文样本（好评+差评）
□ 竞品痛点差异化分析表
□ 核心优化建议不与其他节重复

风险与数据:
□ 风险 ≥5 条（至少 2高+2中+1低）
□ 数据核验说明
□ 全部产品 ID 可点击
```
